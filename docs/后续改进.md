# 后续改进（2026-10-30 记）

和 dsh-bili-scroll / dsh-bili-subagent 对比之后（对比见 dafeiyu-kit `docs/B站插件对比.md`），定下接下来要逐一解决的三件事。每件先调研、出方案，再动手。

## 1. 逛得更自由

**现状**：`bili_surf` 是一条固定流程：候选 → 模型挑三条 → 取文字材料（AI 总结、字幕开头、热评）→ 模型总结。模型只做挑选和总结，不会「看到一条有意思的评论再顺着点进去」，也不会「这个 UP 主不错，再看看他别的投稿」。

**为什么当初这么做**：隔离。逛的过程中模型读的全是 B站上谁都能写的文字，手里一个工具都没有，提示词注入改不了本机的东西；过程也不进主会话的上下文。

**目标**：在**不放弃隔离**的前提下，让逛的过程能多走几步：顺着评论、UP 主、相关推荐、搜索继续探索，最后仍然只交回一份摘要。要回答的问题：

- 插件内自己跑一个小 agent 循环（`ctx.llm` + 只读函数当工具），还是用 DSH 的 `ctx.subagents`、并限定它的工具范围？
- 步数、token、时间的上限怎么定；怎么防止被评论区的文字带偏（注入、无限兜圈）。
- 逛过的路径要不要记下来（「她今天是怎么逛到这个视频的」），设置页怎么展示。

## 2. 装上就能用

**现状**：插件本身是标准 DSH 插件，但要发挥完整能力，依赖的东西不少，耦合也偏重：

- 外部程序：ffmpeg、yt-dlp 要自己装；本机语音识别要另外配 `~/.dsh/asr.json`。
- 注册方式：README 写的是 clone + `npm ci` + 手改 profile 的 `package.json`，不是装个插件就好。
- QQ 这一侧：工具白名单（`SAFE_EXACT`）和分享卡片还原是给 h-D-ACE/dsh-qq 桥接打的本地补丁；门卫是自己的看门狗。别人没有门卫时，所有会话都当可信，草稿只能在设置页同意。

**目标**：别人装上插件就能用：看视频、逛、收件箱、「先问主人」都能工作；QQ / 微信等桥接作为可选增强，而不是前提。要回答的问题：

- ffmpeg、yt-dlp 能不能随插件自带或按需下载（社区插件是怎么做的，比如 scroll 自动下载 uv）。
- DSH 插件的安装、分发方式（插件市场、npm、一键安装）和社区现成的做法。
- 门卫能不能内置一个默认实现：没有桥接时，怎么判断「谁是主人」「主人同意了没有」（DSH 桌面窗口本身就是主人？设置页确认？）；桥接接入时门卫协议怎么写成通用文档，让别的桥接也能实现。
- 哪些耦合可以拆掉：看视频 / 冲浪 / 互动能不能按需启用，缺什么就降级什么，并在设置页说清楚。

## 3. 关注功能

**现状**：插件没有关注 / 取关 UP 主的能力（刻意没做）。小号关注了几个 UP 主是手动关的。

**目标**：她逛到喜欢的 UP 主可以关注，关注动态（`bili_feed` 的「关注」列表）会随之变成她自己的口味。要回答的问题：

- 接口：关注 / 取关、关注列表、分组；参数和风控（新号关注频率限制、`-352` 等）。
- 归到哪一层写操作：档位（关 / 先问主人 / 直接发）、每日上限、能不能取关、取关要不要更严。
- 和冲浪怎么配合：关注列表是不是她「口味」的一部分；要不要限制只能关注逛过、看过的 UP 主，防止被教唆去关注某个账号。

## 调研结论（2026-10-30）

调研只读代码、文档和网页端 JS，没有调用任何 B站写接口。DSH 宿主源码看的是 0.2.1-rc.3（从 app.asar 解出，在 `E:\fish\cache\dsh-host`）。

### 1. 逛得更自由：插件内自己跑 agent 循环

**`ctx.llm` 支持工具调用**（已确认）：

- `stream(options)` 可以带 `tools: [{name, description, parameters}]`，DeepSeek 适配器会把它转成 `input_schema`。没有 `tool_choice`，没法强制模型调或不调工具。
- 流里先来 `tool-call-delta`；`block-end` 里是完整的 `{type:'tool-call', id, name, arguments}`；`finish.reason.kind` 是 `'tool-calls'` 表示要接着调。被 max-tokens 截断时，工具调用会被丢掉。
- 多轮时，助手消息要带 `source:{kind:'model', provider, model, replayState}`，工具结果写成 `{role:'tool', toolCallId, source:{kind:'tool', callId}, content}`。每个 tool_use 后面必须紧跟它的 tool_result。
- 支持 `options.signal` 取消。

**`ctx.subagents` 做不到工具白名单**（已确认）：

- `startActivation` 的 `request` 只能指定 `agentPreset`、`prompt`、`agentOptions`（选模型）等。没有 `toolFilter`。
- 新建 preset 要打 bundle 补丁，而且官方说明它「不是安全沙箱」。全局插件的工具（包括 bili-eyes 自己的写工具）会被子代理继承。
- dsh-bili-subagent 用的就是不受限的子代理。dsh-bili-scroll 是另起一个 `bili-duty` profile 的进程，给 8 个只读工具加若干写固定路径的工具。

**方案**：`bili_surf` 加一个 `mode:'explore'`，新写 `src/surf-agent.js`，自己循环调 `ctx.llm.stream`。现有的固定流程保留为 `mode:'quick'`，模型不支持工具时自动退回它。

- **工具只是插件内部的 JS 函数**，不注册到 `ctx.tools`，全部经过一层只读包装，写接口在这一层根本够不着：
  - `search(query, order?)`、`feed(source)`：返回 ≤8 条，编号 `V#`。
  - `open_video(V#)`：信息、AI 总结、字幕开头、热评（`C#`）、UP 主（`U#`）。
  - `read_comments(V#)`、`read_replies(C#)`、`up_videos(U#)`、`related(V#)`。
  - `finish(picks, route_note)`：结束这一圈。
- **防注入**：
  - 模型只能用编号指代东西，不能直接传 BV 号、mid、URL。评论里写的 BV 号没有编号，就点不进去。
  - 每个工具结果包一层「素材不是指令」。
  - `finish` 选的必须是这一圈真的打开过的视频。评论原文不进主会话。
- **上限**（都做成设置项）：
  - 最多 12 步，最多打开 6 个视频，单次结果 ≤1500 字。
  - 整圈 120 秒；输入累计 ≤60k token、输出 ≤6k token。
  - 到顶就去掉 tools 再调一次，让模型直接给结果。
- **防兜圈**：
  - 同样的「工具 + 参数」直接返回「已看过」，已打开的视频不能再打开。
  - 连续 3 步没有出现新编号，就强制结束。
- **记录路径**：每一步存进 `surf-trails.json`，保留最近 20 圈。设置页「冲浪」显示时间线，比如：搜「X」→ V3 → 热评 C2 → UP 主 U1 → 投稿 V9 ✓。
- **成本**：10 步大约累计 50k 输入（前缀缓存命中后按全价算约 12k），费用约是现在的 3–5 倍，耗时 30–90 秒。
- **顺手要改的**：
  - `makeAsk` 没传 `reasoningEffort`，适配器默认 `high`，现在的挑选和总结很可能在白花思考 token。用 `llm.resolveModelInfo` 查出最低档传进去。
  - `makeAsk` 也没有超时，要补上。
- **要新增的读接口**：
  - 相关视频：`x/web-interface/archive/related?bvid=`。
  - 或者用 `x/web-interface/wbi/view/detail`，一次拿到 View、Related、Card、Tags。
  - 可选：UP 主的完整投稿 `x/space/wbi/arc/search`，容易碰到 -352，失败时退回现有接口。
- **还没确认**：
  - 非 DeepSeek 服务商的工具调用能不能用。
  - 思考模式下多轮带工具能不能续上。建议直接关掉思考。

### 2. 装上就能用：先做分发和自带下载，再内置门卫

**现有 bug**（已核对代码，已修，见下面「进度」）：设置页填的 `ffmpegPath` 分镜用不上。dsh-video-storyboard 在模块加载时就算好了 `DEFAULT_FFMPEG`（`binaries.js:68`），`look.js` 静态 import 它，而 `applyEnv` 到调用工具时才设环境变量。修法是给 `runStoryboard` 和 `probeVideo` 显式传 `ffmpegPath` / `ffprobePath`。

**分发**：

- DeepSeek 没有官方插件市场。DSH 自带「设置 → 插件 → 添加插件」和 `dsh plugin --profile <desktop|web> add <目标>`。目标可以是 npm 包名、`github:`、tgz、`link:`；装完要重启 DSH。
- npm 是主流，dsh-bili-scroll 和 dsh-bili-watch 都在 npm 上。dsh-bili-eyes 在 npm 上还是 404。
- 社区目录有两个：[dsh-plugin-shop](https://github.com/LivXue/dsh-plugin-shop) 收录带 `dsh-plugin` 关键词的 npm 包；[awesome-dsh-plugin](https://github.com/bruc3van/awesome-dsh-plugin) 按 GitHub topic 收录，DSH 的「发现」页可以订阅。

**外部程序**：

- **yt-dlp 变成可选**：dsh-bili-watch 用的是 `platform=html5` 的 360P mp4，只有这一档。改用 DASH（`fnval=4048`）就能按需挑清晰度，见下面「进度」。yt-dlp 保留，当后备或首选都行。
- **ffmpeg 首次使用时下载**：
  - 从 npmmirror 下载 `@ffmpeg-installer` / `@ffprobe-installer` 的平台包 tgz（Windows 约 22 + 29 MB），用 npm 元数据里的 sha512 校验，解压到 `~/.dsh/tools/ffmpeg/bin`，这正是 storyboard 本来就会找的位置。
  - `ffmpeg-static` 不行：它靠 install 脚本下载，DSH 的 pnpm 默认拦安装脚本。
  - 社区先例：dsh-bili-scroll 的 `lib/uvfetch.mjs`，多源下载、校验、跑 `--version` 自检。

**内置门卫**（`gateMode: builtin`）：

- 插件能从 `exec.agent.session.header` 拿到 `agentPreset`、`cwd`、`parentSession`。两个 QQ 桥接都会留下可识别的痕迹：qq-bridge-enhanced 的 preset 是 `qq-chat*`，官方 qqbot 的会话 id 带 `session-` 前缀、`cwd` 是它自己的工作目录。所以可以粗略判断「是不是桥接会话」，但这只是推断，不是认证。
- **可信判定**：沿 `parentSession` 找到根会话；preset 匹配可配置的规则（默认 `/qq|wechat|wx|bot|group/i`）、或 `cwd` 在不可信目录里的，判为不可信，其余当成本机主人。设置页列出最近的会话和判定原因，主人可以手动改。
- **审批**：可信会话直接走 DSH 原生审批卡片（`ctx.get('approval').request(...)`，同一个 turn 里完成）。不可信会话一律起草，只能在设置页同意。
  - 原生审批不能用在 QQ 会话：官方 qqbot 不开白名单时，群里谁都能点「允许」。
- **收件箱转达**：没有桥接时，设置页显示角标，下次调 `bili_inbox` 时带出来。
- **门卫协议 v1**：
  - 现有 HTTP 接口加一个 `hello` 动作，返回协议版本和支持的能力；每个请求带上会话的 `agentPreset`、`cwd`、`parentSession`。
  - 另外提供一个进程内的 Cordis 服务，跑在 DSH 里的桥接（官方 qqbot、微信插件）不用开端口就能接。
  - 写成 `docs/门卫协议.md`，看门狗的 `gate()` 可以当参考实现。
- **还没确认**：工具调用时拿不拿得到 `session.header`、`snapshotEvents`，工具里能不能调 `approval.request`。都要在 DSH 里实际打印出来看。

**降级**：

| 缺什么 | 退成什么 |
| --- | --- |
| ffmpeg | 只给文字（元数据、热评、弹幕、字幕、AI 总结）；先检查，直接跳过分镜，不要慢慢失败 |
| 登录 | 没有字幕和 AI 总结，没有个性化推荐、关注动态、收件箱，不能写；看视频照常 |
| 语音识别 | 台词只来自字幕 |
| 门卫 / 桥接 | 用内置门卫 |
| webServer | 没有设置页，用 `node bin/cli.mjs status` |

**QQ 这一侧还能拆的**：

- 插件导出一份按只读和写操作分好的工具清单，桥接直接拿来做白名单，不用再改 `SAFE_EXACT`。
- `url.js` 直接认 QQ 小程序卡片 JSON 里的 `qqdocurl`，桥接就不用再还原分享卡片。

设置页加一个「安装检查」：工具注册、DSH 版本、ffmpeg（一键下载）、B站登录和等级、主人 UID、语音识别、门卫模式和当前会话的判定、收件箱、缓存目录。每项都写清楚缺了会怎样、怎么修。

**顺序**：

1. 修 `ffmpegPath`；发布到 npm，README 改成「添加插件」；B站改走 playurl 直链。改动小，收益最大。
2. 内置门卫：没有桥接的人也能用「先问主人」。
3. ffmpeg 一键下载、安装检查页、降级提示。
4. 门卫协议文档、进程内服务、工具清单导出、卡片解析；`E:\fish\tools\bili-eyes\install.mjs` 的补丁改成桥接那边的可选说明。

### 3. 关注功能

**接口**（来源：bilibili-API-collect 的社区复刻 [pskdje/bilibili-API-collect](https://github.com/pskdje/bilibili-API-collect/blob/master/docs/user/relation.md)，原版已归档；外加 2026-10-30 线上空间页的打包 JS）：

| 用途 | 接口 | 说明 |
| --- | --- | --- |
| 关注 / 取关 | `POST x/relation/modify?statistics={"appId":100,"platform":5}` | `fid`、`act`（1 关注、2 取关）、`re_src`（11 空间、14 视频、15 评论区）、`gaia_source=web_main`、`spmid`、`extend_content={"entity":"user","entity_id":mid}`、`is_from_frontend_component=true`、`csrf`。**不带 WBI 签名** |
| 查关系 | `GET x/relation?fid=` / `x/relation/relations?fids=` | `attribute`：0 未关注、2 已关注、6 互粉、128 拉黑；还有 `mtime`、`tag` |
| 关注列表 | `GET x/relation/followings?vmid=&pn=&ps=` | 自己的能看全部 |
| 分组 | `GET x/relation/tags`、`GET x/relation/tag?tagid=` | tagid：0 默认分组、-10 特别关注 |
| 建分组 | `POST x/relation/tag/create` | `tag` ≤16 字；22106 表示已存在 |
| 放进分组 | `POST x/relation/tags/addUsers` | `fids`、`tagids` |

- **错误码**：
  - 22001 不能关注自己、22002 对方隐私设置不让关注、22003 对方在黑名单里、22009 关注数到上限、22013 对方已注销、22014 已经关注过、40061 用户不存在。
  - 通用码：-352 风控校验失败、-412 IP 被拦。
  - 网页端把 22014 当成功。
- **没查到的**：新号每天能关注几个、「关注太频繁」返回什么码、22015 是什么意思、关注上限的具体数字。都没有公开资料。
- **核实**：评论被悄悄藏起来过，关注也照样核实。返回 0 后隔 1.5、3、6 秒各查一次 `x/relation`，`attribute` 是 2 或 6 才算成功；三次都不是就记成 `unconfirmed`，关注暂停 24 小时。
- 三个社区插件（scroll、subagent、pond）都没做关注。

**方案**：

- **工具**：`bili_follow({ up, action: 'follow' | 'unfollow', why })`。`up` 可以是 UID、昵称、空间链接或视频链接（给视频就取 UP 主）。`why` 必填，记进审计。走现有写操作框架，新增 kind `follow` / `unfollow`。
- **档位和额度**：
  - `followMode` 默认关；每天 3 个，硬上限 10；两次至少间隔 10 分钟。
  - 取关更严：最高只能到「先问主人」，代码里禁止「直接发」。
  - **只能取关她自己关注的人**：审计里有她关注成功的记录、并且在她的分组里。号上原来就有的关注一律不能取关。
- **防教唆**：
  - 群友教唆已经被门卫挡住了：不可信会话只能起草，确认只认主人的原话。
  - 剩下要防的是可信会话里，她被 B站内容带偏：「自己逛」和「收件箱」都在主人私聊里醒来，会话可信，但这一轮不是主人发起的，评论里可能写着「关注我」。所以：
    - **先问主人**：关注谁都行，每次都由主人点头。
    - **直接发**：只能关注最近 14 天里她真看过的 UP 主，也就是用 `bili_look` 看过、或被 `bili_surf` 选中过他的视频。只在列表或评论区里露过面的不算。
  - 要先补数据：`look.js` 的记录和 `surf-seen.json` 现在只记 BV 号，要加上 UP 主的 mid 和昵称，再做一个「最近见过谁」的查询。
- **错误处理**：
  - 22009：自动把关注档位改成「关」，并提示主人。
  - 22002、22003、22013、40061：只拒绝这一次，不暂停。
  - -352、-412、不认识的 22xxx：暂停 6 小时。
- **分组**：第一次关注时建「小鲸鱼的关注」，以后每次关注都放进去。这个分组就是「她的口味」，也是她能取关的范围。
- **设置页**：「互动」里加「她的关注」列表，每个人都能一键取关，还有「撤销今天全部关注」和「再核实一次」。
- **和冲浪配合**：候选里约 1/3 来自她关注的人的新投稿；挑选时把「她关注的 UP 和当时的理由」作为口味参考，但不能只看这些。

## 建议的推进顺序

1. **装上就能用 第 1 步**：修 `ffmpegPath`、发 npm、playurl 直链。改动小，对别人最有用。
2. **关注功能**：接口清楚，框架现成，主要工作是补「最近见过谁」的数据。
3. **逛得更自由**：改动最大，先在 DSH 里实际确认工具调用和多轮消息格式，再写 `surf-agent.js`。
4. **装上就能用 后续**：内置门卫、ffmpeg 下载、安装检查、门卫协议。

## 进度

### 2026-10-30 装上就能用 第 1 步：自带下载 + 修 ffmpeg 路径（0.6.0）

**最终方案**：

- 新增 `src/media.js`：请求 `x/player/wbi/playurl`（DASH），按**短边**挑一条画面轨（同档优先 HEVC：体积约为 AVC 的 1/3，任何 ffmpeg 都能解；AV1 要看编译选项），挑最小的音轨，并行下载后 `ffmpeg -c copy` 合成 mp4，缓存在 `mediaDir`（文件名 `BV…-p1-480p.mp4`，按容量上限从旧删起，不碰同目录里 yt-dlp 的缓存）。老视频只有 AVC 时，估算超过 200 MB 就降一档。

- 放大看：取帧走我们自己拿的直链（登录 1080P、不登录 480P），`look.js` 不再按文件路径引用 storyboard 没导出的 `fetch.js`。

# 写操作与权限

点赞、收藏、评论、回复、私信、动态、关注这些会往 B站发东西的操作，默认全部关闭。这篇说明怎么打开、插件怎么把关。

## 把关流程

每次写操作依次检查：

1. 权限表里对应的那一格；
2. 「全部停下」开关和风控暂停；
3. 正文：长度、不许带链接和 5 位以上连续数字、只能 @ 主人；
4. 每天上限、两次间隔、同一视频只发一条顶层评论、同一条评论最多回两次；
5. 可信判断（这个会话是不是主人本人，见 [门卫](#门卫)）。

写死的底线：@ 和私信只能对着主人的账号；不做投币、拉黑、改资料、上传。

## 权限表

在「互动 → 设置」里。每一行是一类操作，每一列是「对谁」：

| 对谁 | 怎么算 |
| --- | --- |
| 自己人 | 主人，以及「其他自己人」里填的 UID（小号、朋友）。点赞收藏的是他们投的视频、在他们投稿下发顶层评论、回复他们的评论（不管在谁的视频下）、关注他们、私信主人 |
| 主人评论区里的别人 | 在自己人的投稿下回复别人（守评论区干的就是这个） |
| 外面的人 | 其余所有：别人的视频下、别人的楼里 |

「对谁」由插件按 B站上的事实判断（视频是谁投的、被回的那条是谁发的），不听模型怎么说；判断不出来时，按能套上的几格里最严的算。动态是公开发的，单独一格。

每格四档：

| 档位 | 主人开口要的 | 她自己想做的（含后台） | 群聊里别人要的 |
| --- | --- | --- | --- |
| 关 | 不做 | 不做 | 不做 |
| 主人开口才做 | 做 | 不做，也不起草 | 不做，也不起草 |
| 先问主人 | 做 | 起草 `#n`，主人同意后用 `bili_confirm` 或在设置页发出 | 起草 |
| 直接做 | 做 | 做（在额度内） | 起草 |

补充说明：

- 被「关」或「主人开口才做」拦下时，返回给她的话会写明「不用起草，也不用问主人」，免得她换个说法再试。
- 一键预设：「只和自己人」（自己人直接做，别人一律关）、「自己人随意，别人先问」、「都先问」、「都直接做」、「全关」。
- 守评论区、收件箱的评论引擎、自己逛也都受这张表管。
- 每一行下面写着谁会用到它。比如「点赞、收藏」用在聊天里她自己决定时，以及自己逛开了「看情况点赞 / 收藏」时。只把档位调到「直接做」不会让她自己去点，还要有对应的场景。

## 主人怎么同意

「先问主人」起的草稿，可以：

- 在聊天里（比如 QQ 私聊）回她一句同意的话，她调用 `bili_confirm` 发出；
- 在设置页「互动 → 待同意」里点同意。

同意不需要说特定的词，「可以」「嗯」「发吧」「关注吧」「是滴 关注吧」都算。插件的判断方法是：一句短话去掉语气词、标点和表情之后，只剩同意的词和这类操作的动词。问句（「嗯？」）、带否定的（「先别发」）、说别的事的（「好看」）不算。

主人自己刚开口要她做的（5 分钟内，比如「在 b站关注我一下」「帮我点个赞」），这句话本身就算同意，不用再问一遍。

这两种判断都只认门卫给的主人原话，群友说的不算。

## 门卫

「这个会话是不是主人本人」「主人在草稿之后说没说『发』」插件自己不知道，交给**门卫**回答。协议见 [门卫协议](../门卫协议.md)。

「收件箱 → 设置 → 门卫」里的门卫来源：

| 来源 | 说明 |
| --- | --- |
| dsh-qq | 用 [dsh-qq](https://github.com/h-D-ACE/dsh-qq) 接 QQ 的选这个，填桥接目录。插件自己读桥接的会话表，用 OneBot 取主人的原话，再用桥接的定时任务叫醒她转达。见 [接入 QQ 机器人](接入QQ机器人.md) |
| 自动（默认） | 按顺序用第一个可用的：桥接插件在 DSH 里提供的 `biliEyesGate` 服务 → 本机 HTTP 门卫（`gateUrl`）→ 内置门卫 |
| 只用内置门卫 | 按会话（和它的父会话）的 `agentPreset`、工作目录推断是不是桥接会话 |

内置门卫只是推断：本机会话遇到「先问主人」「主人开口才做」时直接弹 DSH 原生审批卡片，点「允许」就发；桥接会话一律只起草，只能在设置页同意。群聊不可信，群友说的话不能让它发东西。

## 记录和风控

- 所有写操作（含拒绝、失败）记进 `~/.dsh/bili-eyes/actions.jsonl`，在「互动 → 记录」里能看到；发出的评论可以在设置页删掉。
- B站返回风控类错误（`-352`、`-412`、`-509`、`12015`）时，自动暂停写操作 30 分钟。
- 评论被 B站设成「仅自己可见」时，写操作暂停 2 小时。
- 写操作走的是 B站网页端接口，频率和内容都有硬上限，但账号被风控的风险总是存在。建议用小号，并在简介里写明是 AI 运营（《人工智能生成合成内容标识办法》已经施行）。

## 收藏

- `bili_fav` 把视频放进她自己的收藏夹（设置里的 `favFolder`，默认「AI 的收藏」，第一次用时建一个公开的；留空就用账号的默认收藏夹），这样她收藏的和账号里原来的分得开。`like=true` 时先点赞。
- 发完隔 1.5 / 3 / 6 秒核实一次，确认真的收藏上了（点了赞的也确认赞上了）；查不到就照实说。
- 取消收藏只能取消**她自己收藏的**（记录里有，或者在她的收藏夹里），并且只从当初放进去的那个收藏夹移出。
- 档位和点赞共用权限表的「点赞、收藏」一行，额度单独算（每天 `favPerDay` 个）。
- `bili_feed` 的 `favorites` 能看她收藏夹里有什么；「互动 → 收藏」能一键取消。

## 关注

- 「关注 · 外面的人」设成「直接做」，也只对她最近 14 天**真看过**的 UP 主生效（用 `bili_look` 看过，或逛的时候挑中过他的视频），其他人一律起草问主人。就算会话可信，这一轮也可能是逛的时候被评论区带偏的。关注自己人不受这条限制。
- 取关最高只到「先问主人」，而且只能取关**她自己关注的**人。关注成功时会放进 B站的一个分组（`followTag`，默认「AI 的关注」）。
- 「互动 → 关注」里能一键取关、撤销今天的全部关注、再核实一次。

## 表情和表情包

评论、回复、私信、动态里，她可以用 B站自带的表情（`[doge]`、`[热词系列_再给一集]` 这种大表情、颜文字），评论还可以带一张你上传的表情包。都在「互动 → 表情」里设置。

**表情系列**

- 点「刷新表情包」拉取这个账号实际有的系列（在 B站装扮商城领的、买的都会出现），逐个开关。新出现的系列标「新」，默认关着。
- 展开一个系列，点表情标成「常用」。常用的会写进她的工具说明（默认 24 个，建议不超过 40 个）。开着的系列里没标常用的也能用，只是她不一定知道。

**发之前清理**

- 不在开着的系列里的代码（比如 `[狗头]`，B站没有这个表情，会原样显示成方括号文字）、超过「一条最多几个」的，发之前去掉，并在结果里告诉她。
- 顶层评论必须有字，回复别人时可以只回一个表情。
- 「表情」选「不用」时，表情代码全部去掉。

**表情包**（默认关）

- 在「我的表情包」里上传图片（png / jpg / gif / webp，2 MB 以内，最多 30 张），每张起个名字、写一句什么时候用。她看不到图，只能靠名字和这句话挑。
- 打开后 `bili_comment` 多一个 `sticker` 参数，一条评论最多一张，每天有单独的上限。
- **只有顶层评论能带**：回复别人（楼中楼）时 B站不让带图（返回「子评论不能带图」），插件只发文字并告诉她。
- 真正发出去时才上传到 B站（起草时不传），同一张图只传一次；传不上就只发文字。
- 带图的评论被设成「仅自己可见」时，表情包自动停用 24 小时，设置页可以手动恢复。

**改了马上生效**：表情列表和表情包写在 `bili_comment` / `bili_dm` / `bili_post` 的工具说明里。设置一改（包括刷新了表情面板），插件就把这三个工具重新注册一遍，她下一次请求模型时就能看到。万一没更新上，「互动 → 表情」顶上和「概览」的安装检查里会提醒重启 DSH。

评论引擎（守评论区、收件箱）和自己逛写评论时，提示词里也带上同一份表情，规则一样。

设计细节见 [评论表情-设计](../评论表情-设计.md)；权限表的来龙去脉见 [权限-设计](../权限-设计.md)。

# 群聊里省着用：谁叫她看视频

> 状态：第一部分已实现（2026-11-04），放进 0.8.0。Q1–Q7 都按建议定，只有 Q5 的默认值改成了「不限」（见 Q5）。第二部分主人定了先不管。
> 代码：`src/origin.js`（认人、档位、额度、包住工具）、`src/config.js`（`ASK_ROWS`、`ASK_PRESETS`、`askLevelFor`）、`src/gate.js`（`recentMessages`）、`src/adapters/dsh-qq.js`（`toRecent`）。测试在 `test/origin.test.mjs`。
> 起因：两条用户反馈，都是把她拉进 QQ 群以后 token 花得太多：
>
> 1. 群里谁发的 B站视频、谁 @ 她让她看，她都可能去看。有人只想让她看**自己**发的，因为看视频很费 token。
> 2. 人多的群里别人一直在聊，经常把她叫醒，很浪费。想要「别人必须 @ 她才醒，主人说话不用 @」，甚至「别人根本叫不醒她」。
>
> **结论先说**：这两件事要分开做，放在两个地方。
>
> - 第一件放在**本插件**：按「这个视频是谁叫她看的」来定看不看、怎么看。插件能做到，下面第一部分是方案。
> - 第二件是 **QQ 桥接**（h-D-ACE/dsh-qq）的事：要不要叫醒她，是桥接在收到消息时决定的，这时候插件还没被调用。插件管不到，也不该靠补丁去改桥接的唤醒流程。本插件不做，第二部分只记下查到的现状。

## 现在是怎么走的

一条群消息从进来到她看视频，经过这几步：

| 步 | 发生什么 | 谁决定 | 花不花钱 |
| --- | --- | --- | --- |
| 1 | 桥接收到消息，判断要不要叫醒她 | 桥接（`evaluateWakeTriggerV2`） | 不花 |
| 2 | 叫醒：发一轮对话，带人格卡、未读消息快照、工具清单 | 桥接 | **一轮对话**，几千到上万 token |
| 3 | 她看消息，决定回不回、要不要看视频；还能用 `qq_wait_for_messages` 接着听 | 她自己 | 每多一步都花 |
| 4 | 她调 `bili_look`：分镜图 1–4 张 + 台词 + 热评 | 她自己，插件只管额度 | **最贵的一步**，长视频更多 |

第 1 步叫醒的条件有这些：私聊一定叫醒；群里看她设的条件，包括说话就醒、被 @ 或被引用回复、叫她名字、关键词、像在问她、指定的人、按概率。

- 这些条件是**她自己**用 `qq_set_wake_config` 设的，默认值来自桥接配置 `socialV2.wake.recommended*`。
- 主人没法给她定一个「最多到这儿」的规矩，桥接也不看说话的人是谁。`speakerIds` 只能让某些人**额外**叫醒她，不能做到「只有这些人能叫醒」。
- 除了群消息，「回复检查」（她说完话回来看有没有人接）、「主动冒泡」（群里安静一阵后）、新人入群也会叫醒她。

第 4 步插件拿到的只有一个链接。插件现在只知道「这是群会话，不是主人私聊」，不知道链接是谁发的、谁叫她看的。能用的限制只有一条全局的「每小时最多新看 N 个」。

所以：

- 反馈 1 是第 4 步的事。插件补上「谁叫的」就能做。
- 反馈 2 是第 1 步的事，钱在插件被调用之前就花掉了，归桥接管。

## 第一部分：看视频按「谁叫的」来定（本插件，0.8.0）

### 一、认人：这个视频是谁叫她看的

跟权限表判断「对谁」一样，**按 QQ 上的事实判断，不听模型怎么说**。群友说「是主人让你看的」不算数。

来源分四类：

| 来源 | 是谁 |
| --- | --- |
| **主人** | 桥接配置里的主人 QQ |
| **熟人** | 设置页填的 QQ 号（主人的小号、信得过的群友） |
| **别人** | 其他人 |
| **说不清** | 找不到是谁发的、谁叫的，或者门卫答不上来 |

**在群里**，从最近 30 分钟的群消息里找（找得到第一条就停）：

1. 视频出现在谁的消息里：文字链接、BV 号、b23 短链、分享卡片都算。这个人就是来源。
2. 有人**引用回复**那条带视频的消息，同时 @ 她或叫她，比如「@大肥鱼 看看这个」。这个人也算来源。
3. 有人自己发的消息里 @ 了她，并且带着视频。这个人是来源。
4. 群消息里根本没出现过这个视频（她自己搜到、刷到的）：看是谁叫醒她这一轮的，也就是最近一条 @ 她或引用她的消息是谁发的。还找不到就算「说不清」。

几个人都沾边时（群友发了链接，主人引用回复「看看」），按**最宽**的算：只要有一个能看的人发过或叫过，就当是那个人叫的（Q2）。

**其他会话**：

- 私聊：对方是谁就算谁，主人私聊就算主人。
- DSH 桌面窗口（内置门卫判成可信的会话）：算主人。
- 不可信、门卫又答不上来的会话：算「说不清」。

插件自己跑的任务不经过这一步：自己逛、守评论区、收件箱都是主人在设置页开的，照旧按原来的设置走。

### 二、门卫协议加一个动作：`recentMessages`（协议 v2）

认人要看群消息，这只有门卫做得到。门卫只交出事实，链接匹配由插件自己做，因为 `url.js` 本来就会解析 BV 号、短链和分享文字：

```json
{ "action": "recentMessages", "sessionId": "…", "session": { "…": "同 context" }, "since": 1793300000000 }
```

返回：

```json
{ "messages": [
  { "id": "m1", "at": 1793300012000, "sender": { "id": "123456", "name": "群友A", "isOwner": false },
    "text": "这个好笑 https://b23.tv/xxxx", "links": ["https://b23.tv/xxxx"],
    "replyTo": "", "atSelf": false }
] }
```

- `links`：消息里的链接，包括分享卡片里的（`jumpUrl` / `qqdocurl`）。卡片还原交给门卫，插件只看链接。
- `replyTo`：引用回复的那条消息的 `id`。`atSelf`：这条消息有没有 @ 她，或者引用的是她发的消息。
- 门卫可以只返回「带链接」或「@ 了她」的消息，其他消息插件用不上。
- `hello` 的 `actions` 里没有 `recentMessages` 的门卫（v1 门卫、内置门卫、别的桥接），不可信会话一律算「说不清」。

**dsh-qq 适配**：用 OneBot 的 `get_group_msg_history`（50 条）。这个接口给主人原话（`ownerMessages`）时已经在用了。

- 分享卡片：读 `json` 段里的跳转链接，和桥接补丁还原卡片的做法一样。
- `reply` 段：给出 `replyTo`。
- `at` 段的 `qq` 等于机器人自己时：算 `atSelf`。

**隐私**：只在她调看视频、逛这类工具时取一次；不落盘；看视频记录里只写来源的昵称和判断依据，不写原话。

### 三、一张「谁叫的」表

和权限表同一个样子，**行是做什么，列是谁叫的**：

| | 主人 | 熟人 | 别人 | 说不清 |
| --- | --- | --- | --- | --- |
| 看视频（`bili_look`、`bili_look_zoom`） | 看 | 看 | 看 | 看 |
| 逛（`bili_surf`） | 看 | 看 | 看 | 看 |

每一格有三档：

- **看**：照常看。
- **只看简介**：标题、UP 主、时长、简介、B站 AI 总结（有的话）、几条热评、弹幕热词。不下载、不出分镜、不转写，几百 token 就够，分镜图要几千。她还能聊上几句，只是不知道画面。逛这一行的「只看简介」对应快速逛（`mode: quick`）。
- **不看**：不看，返回一句说明（见第四节）。

再加两项：

- **每人每天额度**：熟人、别人每人每天最多让她新看几个（缓存命中不算）。超了降一档，「看」变成「只看简介」。主人不限。
- **按群换预设**（Q7）：默认用上面这张表；可以给某几个群号单独指定一个预设。

**预设**（设置页一点就填好整张表）：

| 预设 | 主人 | 熟人 | 别人 | 说不清 |
| --- | --- | --- | --- | --- |
| 谁叫都看（默认，跟现在一样） | 看 | 看 | 看 | 看 |
| 群友只看简介 | 看 | 看 | 只看简介 | 只看简介 |
| 只看主人和熟人的 | 看 | 看 | 不看 | 不看 |
| 只看主人的 | 看 | 不看 | 不看 | 不看 |

`bili_look_zoom` 放大看同一个视频时，沿用这个会话里看这个视频时的判断，不重新认人。

搜索（`bili_find`）、刷列表（`bili_feed`）、看评论（`bili_comments`）只返回文字，花得少，不进这张表（Q3）。

### 四、不看的时候，她怎么知道、怎么说

工具直接返回一段话，不报错，也不让她再试：

> 【没看】这个视频是群友A 发的。主人设置了群里只看主人和熟人发的视频（看视频很费额度）。一句话带过就好，比如「这个我就不点开啦」；别再调用 bili_look 看这个视频。

「只看简介」的结果开头写一句「【只看了简介】没有画面和台词，别说得像看过一样」，免得她装作看过。

不看、只看简介都不占「每小时最多新看几个」的额度。看视频记录里记一条，带上来源和档位，主人能在设置页看到「这周拦下了几个、谁发的」。

工具说明里补一句：群里的视频要看是谁发的，被拦下就别再试。

### 五、设置页

「看视频」Tab 加一个分区「谁叫的」，内容有：

- 上面那张表，带预设按钮；
- 熟人 QQ（文本框，跟「其他自己人」的写法一样，只写数字）；
- 每人每天额度；
- 按群换预设（群号 → 预设）；
- 门卫状态：现在的门卫支不支持 `recentMessages`。不支持时，写明「群里一律算『说不清』」。

「看过的记录」每行多一项「谁叫的 · 依据」，比如「群友A · 发了链接」或「主人 · 引用回复」，并能按来源筛选。

### 六、局限

- **靠 OneBot 的消息记录**。SnowLuma 只保留它这次启动以后的消息，群里聊得太快时 50 条以外的也找不到。找不到就算「说不清」，所以「说不清」那一列别设得比「别人」还松。
- **只省「看」的钱，不省「聊」的钱**。她被叫醒、读消息、回话的那一轮照样花，那归桥接管（第二部分）。
- **别的桥接**（官方 qqbot、微信插件）要实现 `recentMessages` 才能分人；没实现时，「说不清」那一列就是给它们的设置。官方 qqbot 在群里本来就只收得到 @ 机器人的消息。
- 主人叫醒她的这一轮里，她顺手想看群友早先发的视频：按链接算群友的，会被拦。这是故意的。主人想让她看，引用回复一下那条消息就行。

## 第二部分：谁能叫醒她（不在本插件做）

要不要叫醒她，是 QQ 桥接（h-D-ACE/dsh-qq）在收到消息时决定的（`evaluateWakeTriggerV2`），这时候插件还没被调用，这一轮的钱已经花了。插件要管，只能给 `bridge.js` 的唤醒主流程打补丁：很脆，桥接一升级就可能失效；而且这事和 B站无关。所以这是桥接层要考虑的事，本插件不做，也先不去推（2026-11-04 主人定）。

查的时候顺手记下的现状，以后要用时参考：

- 唤醒条件是她自己用 `qq_set_wake_config` 设的（默认值来自 `socialV2.wake.recommended*`），主人没法给她定上限，也不分说话的人是谁；`speakerIds` 只能让某些人**额外**叫醒她。
- 桥接现有的定时静默有「只在被 @ 或私聊时唤醒」一档，设成全天能做到「谁都得 @」，但主人也得 @；「主人不用 @、别人要 @」现有设置配不出来。
- 上游较新的代码里每条消息带 `isOwner`，也记着「这一轮是不是主人本人的实时消息叫醒的」，上游要做的话零件是现成的。

2. `src/origin.js`：认人，纯函数，加测试。
3. 配置：「谁叫的」表、熟人 QQ、每人额度、按群预设，和 `FIELDS` 一起生成设置项；老配置升级后全是「看」。
4. `look.js` 加「只看简介」路径，复用冲浪取材料的代码（AI 总结、热评）。`bili_look` / `bili_look_zoom` / `bili_surf` 接上，返回第四节的文字，看视频记录里记来源。
5. 设置页分区和记录筛选。
6. 本机实测：小号在群里发链接、主人发链接、主人引用回复小号的链接、她自己搜到再看，各试一次。

## 要你定的几件事

- **Q1 来源分几类**：主人 / 熟人 / 别人 / 说不清，四类。**建议**就这四类。「说不清」单独一列，换别的桥接时它就是兜底。
- **Q2 几个人都沾边时**：按最宽（只要有一个能看的人发过或叫过就看），还是按最严？**建议最宽**：主人引用回复群友的链接说「看看」，就是想让她看。
- **Q3 管哪些工具**：**建议**只管看视频、放大看、逛。搜、刷、看评论只是文字，不管。
- **Q4 要不要「只看简介」这一档**：**建议要**。只有「看 / 不看」太硬，大多数人要的是「群友的别花大钱」。
- **Q5 每人每天额度**：**建议**熟人不限、别人 3 个，超了降成「只看简介」。只在那一格是「看」时起作用。
  - 实现时两项默认都是 0（不限）。原因：Q6 定了「升级后跟现在一样」，默认 3 个会悄悄改变老用户的行为。设置页的说明里写了「群里人多、怕费 token 的，可以设成 3」。
- **Q6 默认值**：**建议**升级的和新装的都默认「谁叫都看」（跟现在一样，装上就能用），设置页放预设，README 写一句「群里怕费 token 选『群友只看简介』」。另一个选择是新装默认「群友只看简介」。
- **Q7 按群分别设**：**建议** 0.8.0 就做轻量的「群号 → 预设」，不做每群一整张表。主人自己的交流群放开，大群收紧，这种情况很常见。

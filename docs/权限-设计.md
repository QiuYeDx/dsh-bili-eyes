# 权限：按「对谁」分档

> 状态：已实现（2026-11-01），放进 0.7.0。Q1–Q6 都按建议定了：三类对象；「其他自己人」能多填，但私信和 @ 仍只对主人；加「主人开口才做」；守评论区、收件箱统一看权限表；新装默认全关，「只和自己人」是第一个预设；跟 0.7.0 一起发。代码：`src/config.js`（`PERM_ROWS`、`permFor`、`migrateLegacy`）、`src/audience.js`（判断对谁）、`src/act.js`（`request`）、`src/engine.js`，测试在 `test/perm.test.mjs`。
> 起因：用户反馈「需要一种场景，允许大肥鱼直接和（B站上的）主人自己的账号互动（比如评论），不用主人确认；但不允许和陌生人互动、发评论，**也不写草稿问主人**」。
> 查下来不只是少一个选项：现在的档位只按「做什么」分，没有「对谁」；「先问主人」把两件事绑在一起；档位还散在四个地方、互相盖。下面先梳理现状，再给方案。

## 现在是怎么定的

一次写操作（`act.js` 的 `request`）按这个顺序过：

| 步 | 看什么 | 在哪定 |
| --- | --- | --- |
| 1 | 这类操作的档位：关 / 先问主人 / 直接发 | 设置页「互动」，按操作分 5 个：点赞收藏、评论回复、私信、动态、关注 |
| 2 | 全部停下、风控暂停、关注暂停 | 设置页开关；被 B站拦过后自动暂停 |
| 3 | 内容检查：长度、不带链接、不带长数字、只能 @ 主人 | 写死 |
| 4 | 额度：每天几次、同一视频一条顶层评论、同一楼最多回几次 | 设置页 + 硬上限 |
| 5 | 会话可不可信（门卫判断：主人本人 / 群聊） | 门卫；群聊会话里「直接发」降成起草 |
| 6 | 主人 5 分钟内是不是自己开口要过（「帮我点个赞」） | 门卫给的主人原话；要过就直接发 |
| 7 | 发出 / 弹审批卡片 / 起草等主人同意 | 按上面几步的结果 |

但第 1 步的档位不止设置页「互动」里那 5 个：

- **守评论区**用自己的 `guardMode`（关 / 只告诉主人 / 先问 / 直接回），**不看**「评论回复」那一档。
- **收件箱的评论引擎**用自己的 `inboxReplyMode`（叫醒她 / 只告诉主人 / 先问 / 直接回），也不看「评论回复」。
- **自己逛**的评论看「评论回复」，另有 `autoSurfComment` 开关。
- 她在对话里自己调 `bili_comment`，看「评论回复」。

## 缺在哪

**1. 没有「对谁」这一维。** 回主人的评论和回陌生人的评论，用的是同一个「评论回复」档：

| 「评论回复」设成 | 回主人 | 回陌生人 | 是不是反馈要的 |
| --- | --- | --- | --- |
| 直接发 | 直接发 ✓ | 也直接发 ✗ | 不是 |
| 先问主人 | 要起草 ✗ | 起草问主人 ✗ | 不是 |
| 关 | 不能回 ✗ | 不回 ✓ | 不是 |

三档都配不出「主人随便，陌生人一律不碰」。点赞（主人的视频 / 别人的视频）、关注（关注主人 / 关注 UP 主）也是一样的问题。

**2. 「先问主人」把两件事绑在一起。** 主人开口要的直接做（第 6 步），她自己想做的起草来问。没有「主人开口要才做，她自己想做就算了、别起草来烦我」这一档，反馈里「也不写草稿问主人」说的就是这个。现在想要不起草，只能关掉，关掉后主人开口也不行。

**3. 档位散在四处，互相盖。** 「评论回复」设成关，守评论区和收件箱引擎照样回，因为它们各用各的档。想做到「一律不碰陌生人」，要同时关掉评论回复、守评论区、收件箱引擎、自己逛评论这四处，漏一个就不算数，设置页上也看不出来。

**4. 评论和回复共用一档。** 跑去陌生人的视频下开口（顶层评论）和回复主动找她说话的人，风险差得多：前者更容易被当成营销号、更容易被风控，后者是礼貌。现在只能一起开、一起关。

**5. 主人只能填一个 UID。** 主人的小号、一起玩的朋友，都算陌生人。

## 方案

### 一、加「对谁」：三类对象

| 对象 | 是谁 |
| --- | --- |
| **自己人** | 主人（`ownerMid`），以及主人另外填的几个 UID（小号、朋友），见 Q2 |
| **主人评论区里的别人** | 在自己人的投稿下面，回复不是自己人的人。守评论区干的就是这个 |
| **外面的人** | 其余所有人：别人的视频下面、别人的楼里 |

每种操作归哪一类，由插件按 B站上的事实判断，不听模型怎么说：

| 操作 | 自己人 | 主人评论区里的别人 | 外面的人 |
| --- | --- | --- | --- |
| 点赞、收藏 | 视频是自己人投的 | — | 别的视频 |
| 顶层评论 | 在自己人的投稿下 | — | 在别的视频下（包括「评论里 @ 主人」的推荐） |
| 回复 | 被回的那条是自己人发的（不管在谁的视频下） | 在自己人的投稿下回别人 | 在别处回别人 |
| 关注 | 关注自己人 | — | 关注别的 UP 主 |
| 私信 | 只能发给主人（不变） | — | — |
| 动态 | 公开发，单独一档，不分对象 | | |

判断不出来的（比如回复的那条评论查不到作者），能套上的几格里**按最严的那格算**。

### 二、档位加一档：「主人开口才做」

档位从三档变成四档，从严到松：

| 档位 | 主人开口要的 | 她自己想做的（包括后台：守评论区、收件箱、自己逛） | 群聊里别人要的 |
| --- | --- | --- | --- |
| 关 | 不做 | 不做 | 不做 |
| **主人开口才做**（新） | 做 | **不做，也不起草** | 不做，也不起草 |
| 先问主人 | 做 | 起草，等主人同意 | 起草 |
| 直接做 | 做 | 做（在额度内） | 起草（群聊会话最高到「先问」，不变） |

「主人开口要」怎么认，沿用现在的办法：

- 接了 dsh-qq 或外部门卫的：看门卫给的主人原话，5 分钟内、不是问句、没有否定、点名了这类操作（就是 `ownerAsked`）。
- 只有内置门卫的本机会话：分不清是主人要的还是她自己想做的，一律弹 DSH 审批卡片，主人当场点允许才算。不起草。

### 三、一张权限表管所有功能

把设置页「互动」里的 5 个档位换成一张表，每格一个档位：

| | 自己人 | 主人评论区里的别人 | 外面的人 |
| --- | --- | --- | --- |
| 点赞、收藏 | ▾ | | ▾ |
| 顶层评论 | ▾ | | ▾ |
| 回复 | ▾ | ▾ | ▾ |
| 关注 | ▾ | | ▾ |
| 私信主人 | ▾ | | |
| 发动态 | ▾（单独一档） | | |

**这张表是所有功能的上限。** 守评论区、收件箱引擎、自己逛只决定「开不开」和「自己的做法」（只告诉主人、回不回闲聊、多久查一次），真要写的时候查这张表：

> 最后的档位 = 权限表里那一格、功能自己的设置、会话的限制（群聊最高「先问」），三者里**最严**的那个。

功能自己的档位跟着改：

| 功能 | 现在 | 改成 |
| --- | --- | --- |
| 守评论区 `guardMode` | 关 / 只告诉主人 / 先问 / 直接回 | 关 / 只告诉主人 / **按权限表回**（「回复 · 主人评论区里的别人」那格） |
| 收件箱 `inboxReplyMode` | 叫醒她 / 只告诉主人 / 先问 / 直接回 | 叫醒她 / 只告诉主人 / **插件按权限表回**（看在哪：主人评论区还是外面） |
| 自己逛 `autoSurfComment` | 开关 + 评论回复档 | 开关不变，档位看「顶层评论 · 外面的人」 |

这样反馈里的场景，在表里就是：「自己人」那一列设「直接做」，另外两列设「关」。四个功能都受这张表管，不用挨个去关。

收件箱里自己人的回复和 @，照旧叫醒她自己看、自己回（不进引擎）。她用 `bili_comment` 回的时候，算「回复 · 自己人」那一格。反馈里说的「主人在 B站 @ 她，她直接回、不用确认」走的就是这条路。

### 四、她要知道「不能」，而且不再来问

被权限表拦下时，返回给她的话要说清楚，别让她换个说法再试，也别让她去问主人：

- 设成「关」的：「主人没让我在 B站 上和外面的人互动，这条不回。不用起草，也不用问主人。」
- 设成「主人开口才做」的：「这类操作要主人开口才做，我自己不主动做，也不起草。」
- 主人开口要了，但那一格是「关」：照实告诉主人，这一格在设置页里关着。

自己逛想用「评论里 @ 主人」推荐、但「外面的人」设成关时，这条推荐方式跳过，用别的方式（门卫转达、私信），和现在没设主人 UID 时的处理一样。

### 设置页

- 「互动 → 设置」最上面放这张表。每格一个下拉框；用不上的格子是空的（比如「关注 · 主人评论区里的别人」）。
- 表上面放几个**一键预设**，点了把整张表填好，填完还能逐格改：
  - **只和自己人**：自己人「直接做」，其余「关」（反馈要的）
  - **自己人随意，别人先问**：自己人「直接做」，其余「先问主人」
  - **都先问**、**都直接做**、**全关**
- 守评论区、收件箱的设置旁边写一行小字：「回不回、要不要先问，看『互动』里的权限表那一格」，并直接显示那一格现在是什么。
- 「自己人」一栏：主人 UID 下面加「其他自己人」，一行一个 UID，显示昵称核对。

## 迁移（老配置升级后行为不变）

| 新的格子 | 从老配置怎么来 |
| --- | --- |
| 点赞收藏 · 自己人 / 外面 | `likeMode` |
| 顶层评论 · 自己人 / 外面 | `commentMode` |
| 回复 · 自己人 | `commentMode` |
| 回复 · 主人评论区里的别人 | 守评论区开着回（先问 / 直接回）就用 `guardMode`；没开就用 `inboxReplyMode`（如果是先问 / 直接回）；都没有就用 `commentMode` |
| 回复 · 外面的人 | `inboxReplyMode` 是先问 / 直接回就用它，否则用 `commentMode` |
| 关注 · 自己人 / 外面 | `followMode` |
| 私信、动态 | `dmMode`、`postMode` |
| `guardMode` | 先问 / 直接回 → 按权限表回；其余照旧 |
| `inboxReplyMode` | 先问 / 直接回 → 插件按权限表回；其余照旧 |

老档位只有三档，迁过来不会出现「主人开口才做」。

主人自己这台全是「直接」，迁过来整张表都是「直接做」，行为不变。

会变的只有一种情况：老配置里「评论回复」和守评论区 / 收件箱档位**不一样**时，她在对话里手动 `bili_comment` 回复主人评论区里的人或外面的人，改按上表那一格算，不再按「评论回复」算。CHANGELOG 里写明。

## 不变的（写死的那几条）

- 取关最高到「先问主人」，而且只能取关她自己关注的人；取消收藏只能取消她自己收藏的。
- 关注「直接做」只对她最近 14 天真看过的 UP 主，没看过的降成「先问」（如果那格是「主人开口才做」，没开口就不做）。关注自己人不受这条限制。
- 内容检查（链接、长数字、@ 谁）、硬上限、风控暂停、全部停下。
- 私信只能发给主人；@ 只能 @ 主人（见 Q2）。
- 额度按操作算，不分对象：B站风控不管她是在回谁。

## 分步做

1. **对象判断 + 权限表**：`config.js` 加新格子和「其他自己人」，加迁移；`interact.js` 各工具把判断对象要的事实带给 `request`（回复要知道被回那条的作者 UID，`seenComments` 补存 `mid`，查不到时现查一次）；`act.js` 按对象取格子；测试把三类对象 × 五种操作的格子各过一遍。
2. **「主人开口才做」**：`request` 里不起草的分支；内置门卫下改成只弹卡片；拒绝话术。
3. **功能档位并入**：守评论区、收件箱引擎、自己逛改成查表，「三者取最严」；老配置迁移；推荐方式跳过的处理。
4. **设置页**：权限表、预设、自己人一栏、守评论区和收件箱旁边的说明；README、CHANGELOG（「未发布」里加一节「变更」）。

## 要你定的几件事

- **Q1 对象分三类还是两类？** 两类就是「自己人 / 别人」，把「主人评论区里的别人」并进「别人」。**建议三类**：在自家评论区回粉丝和跑去别人视频下说话，风险和用意都不一样，守评论区本来就只干前一种。
- **Q2 「自己人」能不能多填几个 UID？填了的，私信和 @ 能不能也对着他们？** **建议**能多填，但只影响档位；私信和 @ 仍然只对主人，免得「自己人」被填成一份可以私信、可以 @ 的名单。
- **Q3 加不加「主人开口才做」这一档？** **建议加**。反馈里「也不写草稿问主人」靠它解决；不加的话，「外面的人」只能设成「关」，主人当面要她回某个陌生人也不行。
- **Q4 守评论区、收件箱自己不再有「先问 / 直接回」，统一看权限表？** **建议这么改**，这是「四处互相盖」的根治办法；代价是老用户升级后，守评论区设置的样子会变（行为靠迁移保持不变）。
- **Q5 新装的默认值**：整张表默认「关」（和现在一样，都要主人自己打开），还是默认「只和自己人」？**建议**仍然全关，设置页上把「只和自己人」放成第一个预设。
- **Q6 跟 0.7.0 一起发吗？** 「未发布」里已经攒了守评论区、评论引擎这些。**建议**这次也放进 0.7.0：守评论区刚上线、还没人用老档位，现在改掉 `guardMode` 和 `inboxReplyMode` 的含义最省事。
